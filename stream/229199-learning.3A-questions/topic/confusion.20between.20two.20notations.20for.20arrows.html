fosco (Sep 13 2026 at 08:37):

I have not seen a situation where confusion arises from mixing the two notations, but I would say there are cases where one may feel a tiny bit weird using the second. The feeling I have is that f:x→yf : x \to yf:x→y is a meta-linguistic expression that doesn't require you to commit to a flavour or foundation, and can mean, for example, that "fff", whatever it is, is a proof that "x≤yx \le yx≤y". At the same time, one could say that f∈C[x,y]f \in \mathcal C[x,y]f∈C[x,y] because in a poset (C,≤)(\mathcal C,\le)(C,≤) there is at most one element in each hom- set. The difference is almost imperceptible but I feel something has changed.

After all, we always know what category our objects belong to, so there is no ambiguity.

Sometimes you don't: finite sets, but only isomorphisms/injections/surjections; finite sets, with partial functions; finite sets, and all functions; finite sets, with all relations, not just the functional ones; these are quite different categories. The difference is so noticeable that in the early days Ehresmann pushed to call a category with the name of its arrows rather than with the name of it objects. So, one should say pFun{\bf pFun}pFun, Inj{\bf Inj}Inj, Rel{\bf Rel}Rel, Cont{\bf Cont}Cont (topological spaces and continuous maps)...

I was thinking that we should think of objects as formal symbols marked with the category they belong to. Otherwise, we should get into all kinds of trouble. For example, we want to have a functor C[–,–]:Cop×C→S\mathcal C [–, –]: \mathcal C^{\text {op}} × \mathcal C → \mathcal SC[–,–]:Cop×C→S, and for that to happen we must have a function on objects that sends them to appropriate arrow sets. If objects are not labelled with the category they belong to, we cannot define that function.
